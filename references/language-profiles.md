# 多语言配置

## 核心原则

同一引擎可以接收多种目标语言，但当前只有简体中文通过代表性真实论文回归。
其他语言的配置是实验性起始值，不代表已达到同等翻译和版式通过率。不同语言
不能共用一套未经调整的字体、行距和断行假设；每个作业在样张通过后，把实际
参数冻结到 `job.json`。

## 当前配置

`assets/language-profiles.json` 内置：

| 代码 | 验证状态 | 自动文本层检测 |
|---|---|---|
| `zh-Hans` | 已验证，项目默认 | 汉字 |
| `zh-Hant` | 实验性起始配置 | 汉字 |
| `ja` | 实验性起始配置 | 假名与汉字 |
| `ko` | 实验性起始配置 | Hangul 与汉字 |
| `en` | 实验性起始配置 | 拉丁字母，需结合翻译单元判断 |
| `fr` | 实验性起始配置 | 拉丁字母，需结合翻译单元判断 |
| `de` | 实验性起始配置 | 拉丁字母，需结合翻译单元判断 |
| `es` | 实验性起始配置 | 拉丁字母，需结合翻译单元判断 |

拉丁字母语言之间无法仅靠字符脚本判断“已经翻译”，因此同时使用 `translation.json` 覆盖率、目标语言功能词标记、术语审查和人工复核。功能词检测只负责阻断明显的“原文冒充译文”，不能证明翻译正确。

日语必须出现足够假名，韩语必须出现足够 Hangul，不能只凭汉字误判。简体与繁体中文使用常见变体字做反向风险检查；它能阻断明显错版，但最终仍需人工核对术语和地区用字。

## 新增语言

新增配置至少提供：

- BCP 47 风格代码和别名；
- 书写系统；
- 目标字符检测规则；
- 首选字体与回退字体；
- 正文字号起始值；
- 行距目标与硬下限；
- 标点和断行策略；
- 原文残留检测策略；
- 文件名后缀。

不要复制整个 Skill。语言差异留在配置和少量专用检查中。

## 质量冻结

非简体中文任务先制作至少三类代表页：

1. 普通正文页；
2. 图表或脚注页；
3. 当前文档最密集页。

三类样张通过后，将字体、字号、行距、连字符和例外区域写入 `job.json`。后续批量生成不得自动缩小这些参数。

## 字体

语言配置中的字体是候选列表，不保证每台机器都安装。初始化时记录实际选中的字体；生成前验证字符覆盖；交付前验证字体嵌入和文本复制。
