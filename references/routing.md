# 文档分流

## 为什么先分流

正文论文、量表、统计表、CHI 版式、界面截图和扫描件不应被强行交给同一个渲染器。分流的目的不是预测“能否自动完成”，而是尽早选择风险最低的制作路线。

## 四条路线

### `standard-auto`

适合可靠文本层、规则单栏或双栏、少量简单图表、页面尺寸稳定的正文型论文。可以用 BabelDOC 等引擎生成底稿，但仍执行全部项目 QA。

### `hybrid-complex-pages`

适合大部分页面规则、少量页面包含图内文字、截图、大图、局部表格、特殊标题区或溢出的论文。普通页自动生成，风险页或风险区域单独重建。

### `custom-layout`

适合量表、密集统计表、短标签对齐、固定表单、混合页面尺寸、重复选项网格，以及任何自动候选出现重叠、裁切或缩字的文档。按逻辑单元和区域重建，不按正文 span 覆盖。

### `scan-custom`

适合没有可靠文本层的扫描件：

1. 渲染页面；
2. 按区域 OCR；
3. 核对阅读顺序和识别风险；
4. 翻译；
5. 重建可检索文本层。

## 画像信号

`pdf_profile.py` 估计：

- 文本层覆盖；
- 页面尺寸变化；
- 单栏/双栏信号；
- 图片和矢量绘图密度；
- 表格、表单与量表风险；
- 扫描页风险。

这些是启发式信号。选择路线前必须目视确认复杂页，并在 `job.json` 写明实际路线和理由。

## 复杂内容页先分类

画像只负责提示，不能证明某页简单。全文翻译前必须按原尺寸检查全部原文页，
通过 `set_complex_content.py` 记录复杂页处理计划。以下内容第一次生成就走
专用方法：

| 内容 | 首选处理 |
|---|---|
| 图表、流程图、模型图、直方图、公式 | 元素管线保留原图，图内标签叠中文 |
| 照片、装饰图、不依赖内部文字理解的截图 | 元素管线保留原图，只翻译图注 |
| 承担研究信息的图内文字、界面截图 | 元素管线保留原图，图内标签叠中文 |
| 密集表格、统计表 | 行列与数值全部确定时 `structured-table-rebuild`，否则保留原表区域加中文翻译键 |
| 量表、表单、题项网格 | `semantic-grid-rebuild` |
| 扫描页 | `ocr-region-rebuild` |
| 横向页、混合尺寸、特殊版心 | `custom-page-reflow` |
| 多栏错序、阅读顺序异常 | `manual-reading-order-rebuild` |
| 多种复杂内容叠加 | 按 `mixed-complex` 登记，并选择风险最高的专用方法 |

## 图默认保留，不重画

图的默认路线是元素管线：

```bash
python3 scripts/build_render_plan.py /path/to/job
```

计划按元素类型给出 `preserve-*` 策略，把图整块搬过来，再按坐标把图内标签
叠成中文。这条路不会丢柱子、不会丢坐标轴，也不需要人把图读成数据。
保留下来的元素就是已渲染的元素，图表清单里不需要另写省略理由。

`vector-rebuild` 是可选路径，只在**确认画得出来**时用：载荷必须含
`nodes`、`edges`、`connectors`、`series`、`panels`、`circles`、`levels`
中的至少一种结构。只给标签文字，渲染器画不出任何图形，导出前总检查会报
`VECTOR_REBUILD_PAYLOAD_NOT_DRAWABLE` 并停下构建。

确认存在任一复杂页时，整篇路线最低为 `hybrid-complex-pages`；复杂页占比高、
结构相互依赖或量表/表单贯穿全文时，直接使用 `custom-layout`。不得先使用
普通逐页正文模板，等重叠、缩字、漏图或错序出现后再升级。

`set_complex_content.py` 会为确认复杂页生成 `complex_content.json` 模板。
进入 `translated` 阶段前，表格必须填写行列和单元格，模型图必须填写标签及
边/连线或序列，截图/OCR 必须填写区域，阅读顺序重建必须填写原文块顺序。
只写“已重建”或一段图意摘要不能通过。

截图和普通图片先判断内部文字是否承担证据、操作步骤或变量含义。若不承担，
只翻译图注，不给图片覆盖译文。`figure_inventory.json` 由
`build_render_plan.py` 程序派生，不手写：保留下来的图就是渲染出来的图，
不需要为它写省略理由。

## 引擎政策

- BabelDOC 是候选排版底座，不是验收者。
- 共享同一 BabelDOC 核心的包装器不算独立排版引擎。
- PyMuPDF 的逐 span 替换只适用于短标签，不得用于正文。
- 需要 OCR、图内文字或截图本地化时必须作为显式任务存在；无需本地化的图片
  按保留策略整块搬过来，由程序记进图表清单。

## 升级条件

样张出现以下任一问题，自动路线升级为混合或定制路线：

- 正文字号低于质量配置；
- 行距低于目标；
- 重叠、裁切、越界或阅读顺序错误；
- 承担论文信息的图内或界面文字未翻译；
- 乱码或兼容字符；
- 文字被压紧而附近仍有大面积可用空白。

升级条件是补漏机制，不是复杂页的默认工作流。翻译前已经识别出的复杂内容，
必须从第一个候选开始使用专用方法。
