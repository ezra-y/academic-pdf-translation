# 架构

## 设计目标

- 可复现的版式画像和 QA；
- 强模型在整篇上下文中翻译；
- 翻译内容与 PDF 排版解耦；
- 排版引擎可替换；
- 复杂页面使用显式 override；
- 作业可中断、可恢复；
- 验收结论可追溯；
- 质量门槛不能被工具静默降低；
- 同一核心支持多个目标语言。

## 分层

1. **画像层**：原文清单、哈希、页面结构与路线建议。
2. **内容层**：翻译单元、术语、原文保留策略。
3. **语言层**：字体、书写系统、断行、标点和质量参数。
4. **版式层**：自动底稿、区域重建和页面 override。
5. **QA 层**：技术指标、原文残留、图表清单和风险信号。
6. **检查层**：基础检查始终执行；快速档不做全篇人工复审，平衡和精细档
   都只做一轮，精细档仅扩大返修后的局部确认范围。
7. **集成层**：批次输出、Zotero 和索引读回。

## 稳定接口

- `Workspace/.workspace.json`：Skill 内部工作区根契约；
- `Workspace/<批次>/.work/batch.json`：批次标题、输入数量、原路径、输入副本
  和隐藏作业目录；
- `job.json`：作业状态与冻结配置；
- `source_manifest.json`：原文画像；
- `source-analysis.json`：原文单次扫描凭据，记录缓存键（原文 SHA-256、
  分析 Schema 版本、PyMuPDF 主版本、分析器构建版本）与逐页规模；原始
  `text_dict` 不落盘，派生结论仍以下面两份文件为准；
- `source_structure.json`：原文文字块、坐标、栏位、原生顺序、坐标推断顺序、
  图像与矢量信号；顺序冲突时保留歧义，不静默选边；
- `source_units.json`：初始化时自动生成的冻结原文单元；每项绑定页码、文字块
  和坐标，制作智能体不能自行合并成整页摘要；
- `translation-plan.json`：按章节、标题和页面顺序编排的翻译批次清单，
  含每批单元数、字符数、页码、缓存键和完成状态；重新编排时保留已完成批次；
- `translation-batches/batch-NNNN.json`：单个批次的执行输入，携带论文标题、
  章节标题、锁定术语、前后批次少量上下文和本批单元；
- `translation-cache.json`：按批次缓存的译文结果。缓存键绑定每个原文单元的
  内容哈希、目标语言、术语表哈希、提示版本、模型标识和翻译策略版本；
- `translation.json`：可复用译文；
- `retained_source.json`：合法原文残留；
- `figure_inventory.json`：图表和图内文字状态；
- `complex_content.json`：复杂页在翻译前填写的表格单元格、模型图节点与连线、
  坐标轴、方向、多面板柱图、OCR 区域或阅读顺序载荷；跨页结构同时记录全部
  源页和逐页坐标；
- `layout_overrides.json`：复杂区域与排版例外；
- `work_checkpoint.json`：当前阶段、已落盘页、下一页和阻塞原因；长文默认
  每约 5 页更新，Agent 接管时从这里恢复；
- `candidate_provenance.json`：候选生成器、显示版本、代码构建哈希、制作人、
  原始路径、候选哈希、译文哈希和版式 override 哈希；
- `generator-layout-log.json`：本轮排版器的逐页字量画像、字号/行距搜索过程、
  失败试排、最终层级参数、标题与首段同页结果和消费合同；
- `staging/render-readiness.json`：候选草稿试排完成后的输入总检查，绑定原文
  单元、译文、复杂页载荷、版式配置、字体和排版器试排合同的哈希；
- `staging/preflight-ledger.json`：按正式候选迭代、排版器和代码构建哈希记录
  注册前检查；相同页面内容不重复计数，同一构建最多首检和集中返修后复检；
- `history/iteration-NNNN/`：被替代候选及其译文快照、检查记录、清单、渲染图和对照证据；
- `qa.json`：自动检测证据；
- `reviews/risk-report.json`：自动生成的逐页语义完整性、引文与检索风险；
- `reviews/completeness-audit.json`：正文压缩、句子保留、数字和统计锚点、
  页面错配及图表重建真实性的确定性审计；
- `comparisons/manifest.json`：源译审查图包的原文、候选、页映射、每张审查图
  和审查 PDF 哈希，以及页码覆盖和文件索引；
- `reviews/independent.json`：审校模式的独立检查证据；
- `reviews/rounds.json`：唯一一轮完整复审的轻量记录；
- `reviews/post-repair.json`：集中返修后改动页、相邻页、同类页和关键内容的
  定向确认，绑定本轮 QA、完整性审计和对照图哈希；
- `run-metrics.json`：按阶段记录状态、耗时、模型和可取得的 token 消耗；
- `finalization.json`：正式路径和 Zotero 读回。

JSON 文件是接口，不把译文嵌入论文专属 Python 脚本。修订术语或证据措辞时，只更新翻译数据并重新生成候选。

新作业的 `translation.json` 必须逐项引用 `source_units.json`，原文、页码和坐标
不得修改。它还必须声明完整覆盖口径和精确单元计数，并通过源 PDF 与候选 PDF
的双向文本定位；`figure_inventory.json` 必须声明清点完成、范围和对应候选
哈希。审校模式的独立检查必须绑定原文与候选哈希；孤立的 PASS 不能自动代表
“没有遗漏”。

源文覆盖率按原文字符并集计算，但并集本身不能证明单元映射可靠。多个小译文
单元重复绑定同一大段或近整页原文会被门禁阻断；需要在“覆盖完整”和“逐单元
可追溯”之间同时成立。

统一首版入口先生成候选草稿和排版合同，再刷新一次总检查，最后运行唯一一次
注册前预检。中途失败不注册候选，也不增加正式版本。总检查确认排版器实际
消费了全部冻结单元和复杂页数据。论文专属代码不得重新写死表格、图内数值、
标题或图注。候选预检再运行翻译完整性审计：
`translation.json` 中有目标语言文本不等于全文翻译完成，`figure_inventory.json`
声明为 `vector-rebuild` 也不等于候选中真的存在节点、连线和数值。预检读取
候选 PDF 的实际绘图、图像和文本结构。临时作业先推进到 `candidate` 状态，
保证图形真实性检查不会被阶段条件跳过，再一次性生成全部返修任务。集中返修
后只复检一次；仍失败则修复排版器并产生新的代码构建哈希，不继续围绕单篇
论文循环。

复杂载荷替代旧文字时优先使用逐页源坐标，目标文字相似度只作兼容退路。
跨页结构在所有声明源页上生效；同页存在多项复杂结构时，每项独立计算覆盖
范围，不能把两项之间的标题、方法或正文连带隐藏。

保留原文区域以 PDF 坐标为主、字符串匹配为兼容退路。混合正文与参考文献页
可以登记多个栏位区域；完整性审计按坐标排除这些区域，排版器按左栏到右栏恢复
题录顺序，并去除页眉页脚和孤立页码。段距 QA 同时读取正文与非正文可见内容，
只有两段之间确实为空时才报告异常段距。

纯参考文献页只从冻结的保留区域渲染一次，不重复消费旧译文单元。参考文献
使用冻结配置中的拉丁字体，渲染前清除零宽字符并修复仅由 PDF 断行产生的
URL、DOI 空格。正文出现率只有在候选中确有对应保留区域时才排除参考文献；
页码映射标签属于元数据，不计入正文排版指标。

混合参考文献页的保留区域必须在后续声明、附录或图注之前结束，并可显式指定
插入顺序。逗号年份制等非括号题录也必须作为参考文献识别。复杂表采用表格字号、
网格和原尺寸目视门槛，不套普通正文的缩字与留白门槛；`replace-page-units`
就绪后由复杂载荷承担精确出现检查。图表清单明确标记为 `omit-nonsemantic`
且写明理由的扫描背景可省略，译文中明确保留的正式英文名称不算原文残留。
百分比区间两端按同一单位核对，复杂表文字层错序只豁免已经在结构载荷中出现
的同值单位差异。

结构化表格必须消费表题、多级合并表头、网格、强调行、表注及表格 DOI；
定向模型必须消费节点、箭头、路径标签和协变量分组。四象限图和坐标图必须
消费横纵轴、方向箭头、正负端标签、刻度或类别。单行图内文字按实际高度
排版，不套复杂图最小高度。参考文献字号
从冻结配置范围内计算，题录标题与首条记录连写时先拆分标题，避免中英文标题
重复。缩写和年份核对使用拉丁字符边界，使紧贴中文的正式缩写、年份及中文
世纪年代写法仍能被正确识别。

只有栅格图、没有底层数据的统计图保留原始曲线、点位和相对几何，不根据截图
反推数据重画。载荷可按图的可读性声明显示宽度和最大高度；坐标轴、图例、阈值
及其他承载研究信息的文字必须提供可机读的源文—译文对应，并随原图一起排版。
图内中文键标题与首条译文保持同页。单图由图片和图注共同构成可分配的阅读
单元；多图并排时显示宽度受栏宽约束，并由图组行列容器保持各自图注，不把
无界高度的整组绑定嵌入表格单元格。并排容器超过完整版心高度时改为可分页
纵排，图内文字键使用完整行宽。

同一源页依次出现图、正文和表格时，复杂载荷可锚定到冻结译文单元之前或之后，
按原页阅读顺序插入；锚点必须属于同一源页，且不能与整页替换同时使用。

候选文字层比对按文字块坐标去除固定页眉和页脚孤立页码，再按单元映射顺序拼接
候选页。这样跨候选页的长段仍可连续核验，同时正文中的样本量、年份、量表分数
和统计值不会因清理页码而被删除。

## 首版成功率发布门禁

- 改变分页、图表、图题、保留区域、正文流排或候选文字层比对口径时递增
  显示版本，并由代码自动产生新的构建哈希；
- 新版本先通过包检查和全套自测；
- 使用 `benchmark_corpus.py` 在隔离副本中运行同一代码构建；默认串行，
  并行度作为明确参数记录；
- 再用至少 5 篇代表样本覆盖普通正文、表格或模型图、照片、混合正文与
  参考文献；
- 每篇必须在该代码构建第一次注册前预检返回 `READY_TO_REGISTER`；
- 注册时只有候选哈希、排版器与版本、导出前总检查哈希和图表清单哈希均与
  `READY_TO_REGISTER` 预检记录一致，才绑定图表清单；任一项不一致就清空
  绑定并重新预检；
- 预检报告必须证明临时副本已处于 `candidate` 阶段，并实际执行复杂图形
  真实性检查；
- 失败样本先归因到输入数据、翻译内容或通用生成逻辑。只有通用逻辑修复并
  回归通过后才能继续批量生产，不能以检查器成功拦截替代首版成功。

## 扩展点

新增排版器只负责生成候选，不能重新定义 PASS。可增补：

- 公式比对；
- 表格网格重建；
- OCR 置信度与人工核对；
- 引文图谱校验；
- 图内文字 OCR；
- Zotero 重复项检测。

排版器配置与质量合同分离。

生产代码只实现内容无关的接口与门槛。作者、标题、期刊、学科术语、测量工具、
固定页码、翻译单元 ID 和本机路径都属于作业数据，不得进入通用运行逻辑。
自测可以使用合成标题和固定页码，但不能让测试夹具反向决定生产分支。

`scripts/typography_fit.py` 是排版器可复用的文档级选型核心。它不理解某篇
论文的页码和版式，只接收页面画像与真实排版测量回调；论文专属生成器负责
声明哪些页属于正文、参考文献或复杂结构页。这样可以替换 ReportLab、
BabelDOC 或其他排版器，而不改变“全篇统一字号、逐页真实测量、按模式验收”
的合同。

`scripts/reportlab_layout.py` 是轻量的通用流排层，只处理样式、真实换行
测量、段落放置、溢出和单汉字孤行信号。图表、量表、页面家具和特殊版式仍
留在作业生成器中；核心不演化为绑定单一论文或期刊的万能排版器。

## 可靠性原则

- Skill 包结构与静态契约使用零额外依赖的 `scripts/check_bundle.py` 检查；
- 每项新翻译请求在 Skill 内部 `Workspace/` 建立独立批次；批次只公开
  `input` 和 `output`，可恢复作业与过程证据统一进入 `.work/jobs`；
- 同一请求的全部 PDF 共用一个批次。入口按原文 SHA-256 查找该批次全部活动
  `job.json` 并恢复已有作业，`history`、`staging` 和对照证据目录不计作
  活动副本；
- 兼容旧项目时，向 `init_job.py --job-root` 提供原有统一作业根目录，不迁移
  已经在处理或已验收的作业；
- 带批次工作区记录的新作业只允许把正式译本写入对应 `output`；
- 正式候选注册前先在临时作业副本预检，自动问题不能污染正式版本历史；
- 导出前的 translated 校验和无候选完整性审计使用只读参数，不复制作业；
  只有真正注册并运行候选 QA 的预检使用一个隔离副本；
- 临时副本通过候选阶段校验并推进状态后，才运行候选完整性和图形真实性审计；
- 首版使用 `build_first_candidate.py` 串联试排、总检查和预检，不由调用者
  手工猜测三个步骤的依赖顺序；
- 检查点只能在对应翻译单元已经落盘后前进，同一阶段不能倒退；
- 原文只做一次完整页面解析。`source_analysis.analyze_source()` 打开一次
  PDF，逐页各取一次 `get_text("dict")`、`get_text("blocks")`、
  `get_text("text")`、`get_image_info()` 和 `get_drawings()`；
  `pdf_profile` 与 `extract_source_structure` 消费同一份结果，各自的派生
  逻辑与输出字段保持不变；
- 同一进程内相同文件的 SHA-256 只计算一次。缓存键为绝对路径、文件大小和
  `mtime_ns`，任一变化即失效；正式哈希仍写入各自结果文件，不只存在于内存；
- 脚本输入不原地修改；
- 输出路径明确，JSON 原子写入；
- 无效输入和硬门槛失败返回非零状态；
- 所有启发式结果标记为风险或建议，不伪装成事实；
- 自动 QA 不替代视觉复核；
- 重译不得覆盖上一轮证据；每轮必须有单调递增编号、被替代候选哈希和修复
  原因；同一文件系统优先用硬链接保存不可变快照，失败时回退为普通复制；
- 翻译按批次执行，校验仍然逐单元。批次不改变冻结单元 ID、原文、页码和
  坐标，只决定一次交给模型多少内容；整批不合格时不写入任何译文，
  `translation.json` 保持原样；
- 目标语言参数在作业开始时冻结，避免中途漂移。
